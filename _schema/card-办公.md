# 办公资料卡片格式规范（schema_version: 1）

一张卡片 = 一份办公文档的结构化摘要，**一份一卡**。

> 用途：找通知、找往年的表、找模板，以及**核对关键时间节点**。

## 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| schema_version | 是 | 固定 1 |
| id | 是 | `{年份}-{类别}-{序号}`，如 `2024-通知-0001`。永不更改 |
| 标题 | 是 | 文件标题 |
| 年份 | 是 | 发文年份 |
| 类别 | 是 | 通知 / 报告 / 表格 / 总结 / 制度 / 申报材料 / 会议纪要 / 简历 / 目录 / 其他 |
| 版本 | 否 | 如 V44、2025 年 4 月修订版 |
| 替代关系 | 否 | **被哪份取代 / 取代了哪份**，编号必须写成 Obsidian 双链，如 `取代 [[2024-制度-0003]]`（新旧版本并存时必填） |
| 是否现行有效 | 是 | 是 / 否 / 未提及（依据替代关系判断） |
| 发文单位 | 否 | 校/院/处/系等 |
| 涉及对象 | 否 | 如「全体教师」「新入职博士」 |
| 关键时间节点 | 否 | 截止日期、执行日期等，逐条列出 |
| 要点 | 是 | 3-5 条：这份文件要求做什么 |
| 存档价值 | 是 | 为什么值得留：可作模板 / 有截止纪律 / 需长期备查 |
| 存储模式 | 是 | 存档型 / 引用型 |
| 源路径 | 是 | raw/ 下路径，或引用型原路径 |
| 抽取质量 | 是 | 高 / 中 / 低 |
| 篇幅 | 否 | 页数 / 字数 |
| 标签 | 是 | 从 `_schema/tags.md` 选 |

## 卡片模板

```
---
schema_version: 1
id:
标题:
年份:
类别:
发文单位:
涉及对象:
关键时间节点:
  -
要点:
  -
存档价值:
存储模式:
源路径:
抽取质量:
篇幅:
标签: []
---

## 原件

📎 [点这里打开原件（扩展名）](../raw/{编号}.{ext})

## 备注
（需要提醒自己的事，没有就写"无"）
```

## 硬要求
1. 「关键时间节点」必须逐条列原文日期，**不许改写或概括成"近期"**。
2. 涉及具体人名的，只写职务不写名字（办公材料常涉隐私）。


## 同一份文件的多个版本怎么建卡

**每个版本各建一张卡**（编号里的年份/版本不同），并在两边都用 **Obsidian 双链** `[[编号]]` 互指，
这样在 Obsidian 里点一下就能从新版跳回旧版查历史，反过来也能跳回来。

- 卡片 YAML 的 `替代关系` 字段：写清取代关系，编号一定用双链写法
- 卡片正文加一节 `## 版本关系`，列出现行版本与历史版本

示例（新版卡）：

```
替代关系: 取代 [[2024-制度-0003]]（2024.10.14 修订版）

## 版本关系
- **现行版本**：本卡（2025 年 4 月修订）
- **历史版本**：[[2024-制度-0003]]（2024.10.14 修订）— 已被取代，仅备回查
```

示例（旧版卡）：

```
替代关系: 被 [[2025-制度-0002]]（2025 年 4 月修订版）取代

## 版本关系
- **现行版本**：[[2025-制度-0002]]（2025 年 4 月修订）
- **本卡**：2024.10.14 修订版 — 已被取代，仅备回查
```

**为什么要两边都写**：只在新版写链接，从旧版出发就找不到新版；
两边都写，Obsidian 的反向链接面板也会自动把两者关联起来。
