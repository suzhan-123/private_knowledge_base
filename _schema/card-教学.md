# 教学资料卡片格式规范（schema_version: 1）

一张卡片 = 一份教学资料的结构化摘要，**一份一卡**。

> 用途：备课时快速找到"去年这门课是怎么讲的"，以及跨课程复用素材。

## 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| schema_version | 是 | 固定 1 |
| id | 是 | `{学年}-{课程名}-{类型}-{序号}`，如 `2024-2025-数据结构-课件-0001`。永不更改 |
| 标题 | 是 | 资料名称 |
| 课程名 | 是 | 完整课程名 |
| 学年 | 是 | 如 2024-2025 |
| 学期 | 否 | 秋季 / 春季 / 未提及 |
| 类型 | 是 | 课件 / 教案 / 大纲 / 试卷 / 实验指导 / 习题 / 案例 / 参考书 |
| 适用对象 | 否 | 如「本科二年级」「研究生一年级」 |
| 版本 | 否 | 如 V2、2025 秋季修订 |
| 替代关系 | 否 | 被哪份取代 / 取代了哪份，编号写成 Obsidian 双链，如 `被 [[2025-课件-0003]] 取代` |
| 存储模式 | 是 | 存档型 / 引用型 |
| 源路径 | 是 | raw/ 下路径，或引用型原路径 |
| 抽取质量 | 是 | 高 / 中 / 低 |
| 篇幅 | 否 | 页数 / 幻灯片 N / 字数 |
| 知识点覆盖 | 是 | 覆盖的主要知识点，逗号分隔 |
| 可复用要点 | 是 | 哪些部分下次还能直接用、怎么用 |
| 改进点 | 否 | 下次上课要改的地方（自己记的） |
| 标签 | 是 | 从 `_schema/tags.md` 选 |

## 卡片模板

```
---
schema_version: 1
id:
标题:
课程名:
学年:
学期:
类型:
适用对象:
存储模式:
源路径:
抽取质量:
篇幅:
知识点覆盖:
可复用要点:
  -
改进点:
标签: []
---

## 原件

📎 [点这里打开原件（扩展名）](../raw/{编号}.{ext})

## 内容梗概
（3-5 句：这份资料讲了什么、怎么组织的）
```

## 硬要求
1. 有原文依据或写"未提及"，禁止推测。
2. 「可复用要点」写清**具体能复用的部分**（哪一页的图、哪个例子），不写空话。


## 同一份文件的多个版本怎么建卡

**每个版本各建一张卡**（编号里的年份/版本不同），并在两边都用 **Obsidian 双链** `[[编号]]` 互指，
这样在 Obsidian 里点一下就能从新版跳回旧版查历史，反过来也能跳回来。

- 卡片 YAML 的 `替代关系` 字段：写清取代关系，编号一定用双链写法
- 卡片正文加一节 `## 版本关系`，列出现行版本与历史版本

示例（新版卡）：

```
替代关系: 取代 [[2024-制度-0003]]（2024.10.14 修订版）

## 版本关系
- **现行版本**：本卡（2025 年 4 月修订）
- **历史版本**：[[2024-制度-0003]]（2024.10.14 修订）— 已被取代，仅备回查
```

示例（旧版卡）：

```
替代关系: 被 [[2025-制度-0002]]（2025 年 4 月修订版）取代

## 版本关系
- **现行版本**：[[2025-制度-0002]]（2025 年 4 月修订）
- **本卡**：2024.10.14 修订版 — 已被取代，仅备回查
```

**为什么要两边都写**：只在新版写链接，从旧版出发就找不到新版；
两边都写，Obsidian 的反向链接面板也会自动把两者关联起来。
