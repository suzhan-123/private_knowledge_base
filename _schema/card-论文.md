# 论文卡片格式规范（schema_version: 1）

一张卡片 = 一篇**学术论文**（期刊论文 / 会议论文 / 预印本 / 学位论文）的可引用摘要。**一篇一卡**，放在 `45_论文`。

> 与基金本子卡片的根本区别：本子卡片服务于「**学写法**」，论文卡片服务于「**找弹药**」。
> 写立项依据、研究现状、可行性论证时，这张卡要能立刻回答两件事：
> **这篇能支撑我哪句话**、**该放进本子哪一节**。

> 综述、标准、专利、教材、技术报告**不属于本类**，请用 `card-文献.md` 走 `40_文献`。

## 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| schema_version | 是 | 固定 1 |
| id | 是 | `{年份}-{第一作者姓}-{期刊简称}-{序号}`，如 `2025-Hu-CVPR-0001`。一经分配永不更改 |
| 标题 | 是 | 中文标题；英文论文填原文标题 |
| 一句话总结 | 是 | **30 字以内**说清这篇干了什么，供扫 INDEX 时快速判断要不要点开 |
| 英文标题 | 否 | 中文论文若有英文标题则填 |
| 作者 | 是 | 「第一作者 等 / 通讯：XXX」 |
| 出处 | 是 | 期刊或会议**全称** |
| 出处类型 | 是 | 期刊论文 / 会议论文 / 预印本 / 学位论文 |
| 年份 | 是 | 发表年份 |
| 卷期页码 | 否 | 如 12(3): 456-478；没有写"未提及" |
| DOI | 否 | 有则填，没有写"未提及" |
| 版本 | 否 | 预印本与正式版并存时标注，如"arXiv v2 / CVPR 2025 正式版" |
| 替代关系 | 否 | 被哪篇取代 / 取代了哪篇（同一工作的新旧版本），编号写成 Obsidian 双链 |
| 存储模式 | 是 | 存档型（原件已进 raw/）/ 引用型（原件留在原处） |
| 源路径 | 是 | 存档型填 raw/ 下路径；引用型填原文件完整路径 |
| 抽取质量 | 是 | 高 / 中 / 低 |
| 篇幅 | 否 | 页数 / 图 N / 表 N / 参考文献 N |
| 研究领域 | 是 | 一级/二级，如「人工智能 / 推荐系统」 |
| 核心方法 | 是 | 技术路线 2-3 句，说清"用什么解决什么" |
| 主要结论 | 是 | 2-3 条，每条一句话 |
| 关键数据 | 否 | **可引用的量化结果**：数据集、评价指标、相对提升幅度 |
| 可引用论断 | 是 | 能支撑本子论证的观点，2-3 条。**必须改写，不得照抄原文** |
| 与我的研究关系 | 是 | 支撑我的观点 / 可作对比基线 / 可扩展为我的方向 / 仅背景 |
| 可放入本子的位置 | 是 | 立项依据-研究现状 / 关键科学问题 / 研究方案 / 可行性 / 研究基础 |
| 时效性 | 是 | 发表年 + 距今 N 年，并判断是否仍属前沿 |
| 可复用要点 | 是 | **引用它时该怎么用**：支撑哪句话、与哪几篇组成一组证据链 |
| 标签 | 是 | 只能从 `_schema/tags.md` 选 |
| 关联编号 | 否 | 相关的本子编号或论文编号 |

## 硬要求
1. 每个字段要么有原文依据，要么写"未提及"。**禁止推测填空。**
2. 「可引用论断」一律**改写**，不得出现连续 20 字以上的原文片段。
3. 「可放入本子的位置」必须落到具体小节，不许写"都可以"。
4. 计算机方向论文超过 5 年的，在「时效性」里明确写"仅作背景，不宜作研究现状依据"。
5. 「原文关键句」必须是论文里的**真实原句**，逐字照抄、不得改写，中译要忠实。
   这是全卡**唯一允许保留原文的地方**（其余字段一律改写，不得出现 20 字以上原文片段）。
6. 「局限性与可能的追问」要基于论文自己的 limitation 章节或实验边界来写，
   不要替作者凭空认错；原文确实没写就写「原文未提及局限」。


## 同一份文件的多个版本怎么建卡

**每个版本各建一张卡**（编号里的年份/版本不同），并在两边都用 **Obsidian 双链** `[[编号]]` 互指，
这样在 Obsidian 里点一下就能从新版跳回旧版查历史，反过来也能跳回来。

- 卡片 YAML 的 `替代关系` 字段：写清取代关系，编号一定用双链写法
- 卡片正文加一节 `## 版本关系`，列出现行版本与历史版本

示例（新版卡）：

```
替代关系: 取代 [[2024-制度-0003]]（2024.10.14 修订版）

## 版本关系
- **现行版本**：本卡（2025 年 4 月修订）
- **历史版本**：[[2024-制度-0003]]（2024.10.14 修订）— 已被取代，仅备回查
```

示例（旧版卡）：

```
替代关系: 被 [[2025-制度-0002]]（2025 年 4 月修订版）取代

## 版本关系
- **现行版本**：[[2025-制度-0002]]（2025 年 4 月修订）
- **本卡**：2024.10.14 修订版 — 已被取代，仅备回查
```

**为什么要两边都写**：只在新版写链接，从旧版出发就找不到新版；
两边都写，Obsidian 的反向链接面板也会自动把两者关联起来。
