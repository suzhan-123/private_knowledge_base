# 参考文献卡片格式规范（schema_version: 1）

一张卡片 = 一份**非论文类参考资料**（综述合集、标准规范、专利、教材、技术报告、白皮书、政策文件）。
**学术论文（期刊/会议论文）请放 `45_论文`，用 `card-论文.md`。**

## 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| schema_version | 是 | 固定 1 |
| id | 是 | `{年份}-{类型}-{序号}`，如 `2024-标准-0001`。一经分配永不更改 |
| 标题 | 是 | 文件标题 |
| 类型 | 是 | 综述 / 标准 / 专利 / 教材 / 技术报告 / 白皮书 / 政策文件 / 其他 |
| 年份 | 是 | 发布或修订年份 |
| 发布机构 | 否 | 标准委员会 / 出版社 / 政府部门 / 学会 |
| 版本 | 否 | 如 V44、2025 年 4 月修订版 |
| 替代关系 | 否 | **被哪份取代 / 取代了哪份**，编号必须写成 Obsidian 双链，如 `取代 [[2023-标准-0007]]`（新旧版本并存时必填） |
| 是否现行有效 | 是 | 是 / 否 / 未提及（依据替代关系判断） |
| 存储模式 | 是 | 存档型 / 引用型 |
| 源路径 | 是 | 存档型填 raw/ 下路径；引用型填原路径 |
| 抽取质量 | 是 | 高 / 中 / 低 |
| 篇幅 | 否 | 页数 / 字数 |
| 核心内容 | 是 | 2-3 句讲清它是什么、管什么用 |
| 可引用要点 | 是 | 能支撑什么论断（改写，不抄原文） |
| 可放入本子的位置 | 是 | 立项依据 / 研究方案 / 可行性 / 研究基础 / 不适用 |
| 时效性 | 是 | 是否现行有效、是否需要换新版本 |
| 可复用要点 | 是 | 什么场合该翻它 |
| 标签 | 是 | 只能从 `_schema/tags.md` 选 |
| 关联编号 | 否 | 同主题的其他版本或相关条目 |

## 硬要求
1. 有原文依据或写"未提及"，禁止推测。
2. **同一份文件有多个版本时，每个版本各建一张卡**，并在两张卡里都写清 `替代关系`，
   这样才能一眼看出哪个是现行的。


## 同一份文件的多个版本怎么建卡

**每个版本各建一张卡**（编号里的年份/版本不同），并在两边都用 **Obsidian 双链** `[[编号]]` 互指，
这样在 Obsidian 里点一下就能从新版跳回旧版查历史，反过来也能跳回来。

- 卡片 YAML 的 `替代关系` 字段：写清取代关系，编号一定用双链写法
- 卡片正文加一节 `## 版本关系`，列出现行版本与历史版本

示例（新版卡）：

```
替代关系: 取代 [[2024-制度-0003]]（2024.10.14 修订版）

## 版本关系
- **现行版本**：本卡（2025 年 4 月修订）
- **历史版本**：[[2024-制度-0003]]（2024.10.14 修订）— 已被取代，仅备回查
```

示例（旧版卡）：

```
替代关系: 被 [[2025-制度-0002]]（2025 年 4 月修订版）取代

## 版本关系
- **现行版本**：[[2025-制度-0002]]（2025 年 4 月修订）
- **本卡**：2024.10.14 修订版 — 已被取代，仅备回查
```

**为什么要两边都写**：只在新版写链接，从旧版出发就找不到新版；
两边都写，Obsidian 的反向链接面板也会自动把两者关联起来。
