# 维护与更新

> 这一章讲的是**怎么让这份手册不变成废纸**。

---

## 一、硬规则：改了功能，必须更新手册

写在 `AGENTS.md` **第 12 条**：

> 任何新增或修改的功能（工具、分类、卡片字段、操作流程），
> 都要在 `60_使用手册\` 里补上或更新对应章节，
> 并在 `README.md` 末尾的版本记录表里加一行。

**为什么**：库是给不懂技术的人用的。功能变了手册没变，你下次照着做就会卡住，
然后不得不重新问一遍——那就白建这个库了。

---

## 二、哪些改动需要更新手册

| 改了什么 | 要更新哪一章 |
|---|---|
| 新增分类（比如再加一个 `50_xxx`） | `README.md`（库结构表）、`04_添加新文件.md`（编号规则） |
| 改了卡片字段 | `03_看卡片和找资料.md`（各分类看什么） |
| 改了归档流程 / 工具 | `04_添加新文件.md` |
| 改了检索方式 | `02_Obsidian使用指南.md`、`03_看卡片和找资料.md` |
| 新增了 AI 接入方式 | `07_给四个AI用.md` |
| 改了备份 / 同步规则 | `06_备份与迁移.md` |
| 碰到新的坑（比如某个软件行为怪） | `08_常见问题.md` |
| 任何影响"你日常怎么操作"的变化 | 先想"我下次会不会卡住"，会就写进去 |

---

## 三、更新手册时怎么做

1. **改内容** —— 用大白话，写清"点哪里、输什么、看到什么"
2. **改版本日期** —— 在 `README.md` 顶部的「手册版本」那一行更新
3. **加一行记录** —— 在 `README.md` 末尾的版本记录表追加：

```
| 2026-09-11 | v1.1 | 新增了 XX 功能，手册补了 XX 章节 |
```

4. **同步记进 `_log\CHANGELOG.md`**

---

## 四、每次大改动后的自检清单

让 AI 对着这份清单检查：

- [ ] 手册里提到的**文件路径**是否还存在
- [ ] 手册里提到的**菜单项 / 快捷键**是否还正确
- [ ] 手册里写的**条目数、分类数**是否需要更新
- [ ] 新增功能是否已在手册里有对应章节
- [ ] `README.md` 的版本记录表是否加了新行

---

## 五、定期维护（建议）

| 频率 | 做什么 |
|---|---|
| 每次加功能后 | 更新手册 + 记 CHANGELOG |
| 每月 | 跑一次 `_prompts\08_体检.md`；复制一份到移动硬盘 |
| 每季度 | 通读一遍手册，看看有没有过时的地方 |

---

## 六、手册也有编号规则

`60_使用手册\` 下的文件用两位数字前缀（`01_`、`02_`…），保持顺序稳定。
**新增章节用下一个空号**，不要插在中间重排（会让外部引用断掉）。
